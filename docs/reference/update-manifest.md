# The update manifest (`update.json`)

The contract between a published release and the application. Machine-readable schema:
[`update.schema.json`](update.schema.json). Rationale:
[ADR-0005](../adr/0005-distribute-updates-via-github-releases-with-a-published-manifest.md).

## Where it lives

```
https://github.com/mateussantoos/nsx-manager/releases/latest/download/update.json
```

The filename is **stable across releases**, which is what makes `releases/latest/download/`
resolve. This is a `github.com` web redirect to the release CDN - **not** `api.github.com` - and
is therefore not subject to the unauthenticated REST limit of 60 requests per hour per IP.

Fallback, used only when `github.com` itself is unreachable:

```
https://raw.githubusercontent.com/mateussantoos/nsx-manager/release-metadata/update.json
```

## Example

```json
{
  "schema_version": 1,
  "product": "nsx-manager",
  "version": "0.2.0",
  "tag": "v0.2.0",
  "published_at": "2026-10-01T12:00:00Z",
  "channel": "stable",
  "mandatory": false,
  "min_supported": "0.1.0",
  "min_atmosphere": "1.7.0",
  "changelog_url": "https://github.com/mateussantoos/nsx-manager/releases/tag/v0.2.0",
  "release_notes_url": "https://github.com/mateussantoos/nsx-manager/releases/download/v0.2.0/RELEASE_NOTES.md",
  "assets": [
    {
      "name": "nsx-manager-0.2.0.nro",
      "kind": "app-nro",
      "url": "https://github.com/mateussantoos/nsx-manager/releases/download/v0.2.0/nsx-manager-0.2.0.nro",
      "size": 12880849,
      "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
    }
  ]
}
```

## Fields

| Field | Type | Required | Meaning |
|---|---|---|---|
| `schema_version` | integer | yes | Contract version. A client that sees a **higher** number refuses the manifest and tells the user to update manually. It never guesses at fields it does not know. |
| `product` | `"nsx-manager"` | yes | Guards against a manifest for a different product being served by mistake. |
| `version` | SemVer | yes | The released version, no leading `v`. |
| `tag` | string | yes | The git tag. Must equal `"v" + version`. |
| `published_at` | ISO-8601 UTC | yes | Shown as "released N days ago". |
| `channel` | `stable` \| `beta` | yes | A client on `stable` ignores a `beta` manifest. |
| `mandatory` | boolean | yes | When `true`, the client blocks the main menu until the user updates. |
| `min_supported` | SemVer | yes | The oldest installed version allowed to update in-app. |
| `min_atmosphere` | SemVer | no | Warns, does not refuse - detection is not always reliable. |
| `changelog_url` | https URL | no | Opened by "what's new". |
| `release_notes_url` | https URL | no | Fetched and rendered in the in-app changelog. |
| `assets` | array | yes | At least one, and at least one of `kind: app-nro`. |

### Asset fields

| Field | Type | Meaning |
|---|---|---|
| `name` | string | A **bare filename**. No `/`, no `\`, no `..`, no leading dot. A name that can traverse directories must never reach a filesystem call. |
| `kind` | enum | `app-nro`, `forwarder-nro`, `sd-overlay-zip`. **The client selects by `kind`, never by parsing the filename.** An unknown kind is skipped, not an error. |
| `url` | https URL | Must be a `github.com` release asset. |
| `size` | integer | Bytes. Used for the free-space pre-flight and as a cheap truncation check before hashing. |
| `sha256` | 64 hex chars | Lowercase. **An asset without a verifiable digest is never downloadable.** |

## Two fields that carry real policy

### `mandatory`

The predecessor hid all ten of its tabs whenever *any* newer tag existed
(`main_frame.cpp:94-133`) - an unconditional lockout compiled into the binary. Here it is a
per-release publisher decision. Use it for a security fix; leave it `false` otherwise.

### `min_supported`

Set it above an older version when the SD layout or config format changed in a way the in-app
path cannot bridge. A client below it is told to reinstall from the zip, with the direct link,
rather than being walked into a broken update.

## Forward compatibility

* **Unknown top-level fields are ignored.** New optional fields can be added within
  `schema_version: 1`.
* **Unknown `kind` values are skipped.** A new asset type does not break old clients.
* **A higher `schema_version` is refused outright.** That is the escape hatch for a genuinely
  breaking change: old clients stop rather than misinterpret.

Bumping `schema_version` is a breaking change requiring its own ADR and a `feat(update)!:` commit.

## Generation and validation

Generated by [`tools/release/gen_manifest.py`](../../tools/release/gen_manifest.py) during
`release.yml`, from the built artefacts - sizes and hashes are computed from the actual files, so
they cannot disagree with what is published.

Validated by [`tools/release/validate_manifest.py`](../../tools/release/validate_manifest.py)
**before** the release is created. You cannot ship a manifest the client refuses to read.

The validator also runs against
[`tests/fixtures/manifests/`](../../tests/fixtures/manifests/) in CI, where each fixture records
one required rejection - a hostile asset name, a plaintext URL, a missing digest, a future schema
version. Those fixtures are the specification.

```sh
python3 tools/release/validate_manifest.py --check-fixtures
python3 tools/release/validate_manifest.py path/to/update.json
```
